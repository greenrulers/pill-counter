## 結論

- **平鋪在深色底、不重疊**（藥局的正常做法）：兩張都全對，且沒有橘色誤報。
- **緊密相碰／堆疊**：會少算，但不確定標記會亮起來提醒目視；請把藥撥開再拍。
- **低對比**（紅藥放紅棕底、白藥放白紙）與**雙層背景**（盤子放桌上）：超出設計，請換對比明顯的托盤並拍滿畫面。

## 這輪依真實照片修正的演算法

1. 雜訊水準改用背景峰的半高寬 × 3（上限 70），不再「走到谷底」——木紋等有紋理的背景沒有谷底，舊法會把門檻推進藥的亮度區（Ibuprofen 照片原本只剩 58 個反光點）。
2. 分區背景的「像背景」判定改成「RGB 距離 < 60，或色度相近且亮度 0.5–1.6 倍」——同時容忍托盤漸層與不把暗色藥當背景。
3. 每個元件的拆分上限改用該元件自己的內切圓半徑，混裝大小藥時小藥群不會被砍。
4. 大小不一（內切圓半徑四分位距／中位數 > 0.35）時放寬不確定判定，混裝照片不再整片橘色。
5. 密集排列時若找到的顆數明顯少於面積推算，改用未填洞的距離圖重做頸部測試（Ibuprofen＋caplets 從 24 → 60）。
6. 三類 Otsu 候選加「形狀守門」（中間類像素開運算後存活率 ≥ 50% 才採用），避免把陰影當成一類藥。

合成測試在這些修改後維持 97–98% 完全正確（`node test/run.mjs 400 2`、`… 4`）。
