# 數藥小幫手（Pill Counter PWA）

用 iPhone 相機數藥錠數量、核對處方數量，避免發藥時數錯。個人非營利工具，所有影像都在手機內運算，不上傳任何資料。

## 在 iPhone 上安裝（當成 app 用）

1. 用 Safari 打開部署網址（見下方「部署」）。
2. 點下方「分享」鈕 → 「加入主畫面」→ 「新增」。
3. 之後從主畫面的「數藥」圖示開啟，就是全螢幕、可離線使用（第一次開啟需要連網載入）。
4. 第一次按「拍照計數」時，Safari 會問是否允許使用相機，選「允許」。

## 怎麼用

1. 輸入「預定數量」（可點 28、30、56 等快速鍵）。
2. 把藥平鋪在**深色托盤或深色紙**上，盡量不重疊、彼此留一點空隙，從正上方拍。
3. 按「拍照計數」。畫面上每顆藥都會畫圈並編號，左上角顯示總數與「與預定相符／多幾顆／少幾顆」。
4. 綠圈＝正常；**橘圈＝程式沒把握（相連、形狀怪、靠邊）**，請目視確認；藍圈＝你手動補的。
5. 漏抓的藥：點一下該位置補標記；誤抓的：點一下標記移除。數量會即時更新。
6. 「存紀錄」會把這次的照片（處理後的解析度）、每顆的標記位置、藥名、預定數、數到的數一起存在手機的 IndexedDB 裡（只在這支手機，不上傳）。右上角「紀錄」可看縮圖清單，點進去能看標記圖、改藥名與備註、分享或下載標記圖、「重新開啟修正」後再存會更新同一筆；清單上方可「匯出 CSV」。設定裡可開「辨識後自動存紀錄」。
7. 「相簿」可以選手機裡既有的照片來數（會依 EXIF 自動轉正）。
7. 「即時計數」開啟後，不用按拍照，鏡頭對著藥就會持續顯示數量（較耗電、較粗略；正式核對請用拍照）。

### 拍不好時

| 現象 | 調整 |
|---|---|
| 陰影、反光、托盤刮痕被當成藥 | 設定 → 靈敏度往右（正值）；或開「顯示辨識範圍」看哪裡被塗到 |
| 顏色淺的藥抓不到 | 靈敏度往左（負值）；換深色托盤 |
| 白藥放白紙上 | 幾乎抓不到，請換深色底；深色藥則用白紙 |
| 黏在一起的藥算成一顆 | 把藥撥開一點再拍；確認「自動拆分相連藥錠」有開 |
| 有刻痕的錠被算成兩顆 | 程式會自動合併兩個半圓；若仍錯，點掉多的標記 |
| 藥很小、很多 | 設定 → 解析度 1400；鏡頭靠近一點 |

**辨識結果只是輔助，發藥前仍以目視複核為準。**

## 運作原理（counter.js）

純 JavaScript、不需伺服器，瀏覽器與 Node 共用同一支程式：

1. **背景估計**：取影像外框帶狀區域的眾數色當托盤色，再把影像切成格子，每格各自估一次（修正光線漸層），缺格由鄰格補、再平滑。
2. **特徵圖**：每個像素與局部背景的顏色距離（0–255）。因此白藥配深托盤、深色藥配白紙都能用，不限顏色。
3. **門檻**：先從直方圖的背景峰估出雜訊水準，再在雜訊水準以上做 Otsu 自動門檻（避免藥很少時 Otsu 被托盤自己的明暗差騙走）。
4. **形態學**：閉運算補刻痕、開運算去雜點，半徑依估計出的藥錠內切圓半徑 R 自動調整。
5. **距離轉換（EDT）**：Felzenszwalb 精確歐氏距離轉換。做兩份：未填洞版找波峰（保留三、四顆互靠時中間的小空隙），填洞版做頸部測試與面積。
6. **拆分相連藥錠**：每個連通元件取 EDT 局部極大值 → 非極大抑制 → **頸部測試**（兩波峰連線上的最小 EDT 若明顯小於波峰，中間有「脖子」才算兩顆；長錠、膠囊、有壓印的錠不會被誤拆）→ 面積上限。
7. **後處理**：相鄰兩個半圓合起來很圓就合併成一顆；面積小於單顆中位數 30% 的視為雜點；數量與面積不一致或靠邊的標為不確定（橘色）。
8. **抗雜亂背景（v1.2.1）**：填洞只填比一顆藥小的洞（夾鏈袋外框、托盤格線這種封閉的亮線圈圍出的大洞不填，否則整個袋子內部會變成一個巨大元件）；內切圓遠小於藥、外框很長或面積是內切圓幾十倍的「線／環／網」元件（袋邊、封口線、皺褶反光）直接略過；半徑估計改用內切圓面積加權，幾十條細線拉不低 R。被略過的多時提示「背景雜亂」。
9. **圓形偵測備援（v1.2.2，`blobs.js`）**：分割結果不可靠時（橘色 ≥ 30%、背景雜亂、對比太低、半徑不合理、單一巨大元件、只找到 ≤ 2 顆），改用「中心點法」：亮度 Sobel 梯度 → 每個邊緣像素沿梯度方向對各候選半徑的圓心投票（圓形霍夫轉換）→ 圓周平均邊緣強度取局部極大值 → 圓周 24 個角度的徑向邊緣支持度 ≥ 0.55 才算圓 → 半徑一致性。只在「至少 3 個圓、八成以上是強圓、半徑 ≥ 12 px」時採用。相連的藥錠之間有接觸陰影，所以每顆仍是自己的圓；白藥裝透明夾鏈袋放灰桌上也能數對（`test/real/`）。它只認圓錠，膠囊、長錠仍靠分割法。

## 測試

效能基準（Mac mini，1000×750）：v1.1.1 平均 68 ms／張 → v1.2.0 平均 38 ms／張（距離轉換改步幅版並跳過全背景行列、直行改線性掃描、形態學平面位移表、掃描線填洞、連通元件內部快速路徑）。優化前後用 `node test/snapshot.mjs 300 2 <bmp資料夾> a.json`／`node test/compare.mjs a.json b.json` 比對，合成 400 張與真實 5 張的顆數、座標、半徑、門檻完全相同。

```bash
node test/run.mjs 400 2          # 400 張合成托盤影像（不同托盤色、藥形、相連率、陰影、漸層、雜點）
PC_OPTS='{"threshold":"pct"}' node test/run.mjs 400 2   # 覆寫參數做 A/B
```

失敗案例會輸出到 `test/out/`（畫好標記的 PNG）。目前合成測試完全正確率約 97–98%，誤差多為 ±1 且會被標成橘色。

```bash
node test/bag.mjs                # 回歸：藥裝在透明夾鏈袋裡放灰桌上（2026-10-26 實拍 10 顆被數成 53 的情境）：3 張模擬＋1 張真實照片（test/real/，PNG 由 test/png.mjs 讀），必須正好 10 顆
node test/real.mjs <資料夾>        # 真實照片（.bmp 或 .png），輸出畫好標記的圖到 test/out/
```

真實照片：`node test/real.mjs <含 .bmp 的資料夾>`（JPEG 先用 `sips -s format bmp 檔.jpg --out 檔.bmp` 轉檔）。用維基共享資源的公開授權照片做過初步驗證：平鋪在深色底的兩張（28 顆、10 顆）全對，緊密堆疊與低對比的會少算但會標橘色，見 [docs/真實照片驗證.md](docs/真實照片驗證.md)。另外用食藥署藥品外觀資料集的真實藥錠照片（脈優、康肯、瑪爾胰、可悅您、艾必克凝）合成模擬托盤，15 張（含 60 顆一半相碰）全對，見同一份文件。藥局數藥盤上的實拍仍待組長回饋。

```bash
node tools/make_samples.mjs      # 重新產生 samples/ 範例圖
node tools/make_icons.mjs        # 重新產生 icons/
```

## 本機預覽

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

打開 `http://127.0.0.1:8765/?img=samples/sample1.jpg` 可不經相機直接測試一張圖。

## 部署

純靜態檔案，任何靜態主機都能放（Vercel、GitHub Pages、Cloudflare Pages）。相機與離線快取需要 HTTPS。`vercel.json` 只設定了 `sw.js` 不快取，讓更新能即時生效。

## 關於 PillEye 等商業 app

PillEye（韓國 Medility）、Pill Counting 等商業 app 以相機即時或拍照計數，宣稱準確率 99.99%（廠商數字，無獨立驗證），採月費制，演算法未公開（官方訪談只提到以大量藥錠照片訓練多個模型）。本專案**沒有**反編譯或取用任何商業 app 的程式與模型，而是用公開文獻中成熟的古典影像處理方法（距離轉換＋分水嶺／波峰拆分）從頭實作，並針對藥局情境（托盤、刻痕錠、膠囊、相連）加上自己的規則。要再提升對奇形藥品與重疊的辨識，下一步是用自己拍的照片訓練小型物件偵測模型（例如 YOLO 系列匯出成 ONNX，在瀏覽器用 onnxruntime-web 跑），同樣可以完全離線。

## REA 分析

這台 Mac 裝了 REA（Reverse Engineer Anything）。用它對本專案做過靜態分析與正式網址的網頁 bundle 分析（對外端點 0 個，驗證「不上傳」），對 PillEye 官網做過檢查，也在組長親自下載並同意後，對 PillEye Android 3.14.0 安裝檔做了結構分析：Flutter 應用，安裝檔內沒有任何模型檔，Android 版拍照計數是把照片上傳到 pilleye.io 雲端推論，即時模式只在 iOS 且需專用托盤硬體；原生端的「裝置內偵測」是回傳寫死數值的占位實作。沒有反編譯、複製其程式或模型。做法與結果見 [docs/REA分析.md](docs/REA分析.md)。
